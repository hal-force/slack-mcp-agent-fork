# Triage operations — synthetic dataset (agent-facing)

> **All data here is SYNTHETIC.** No real patient, clinician, or facility data is
> represented. Every row of every table carries `data_classification=SYNTHETIC`.

This is the data an analysis agent reaches **through the Tableau MCP server** to
answer operational questions about AI-assisted nurse assignment — which nurse
should take a new patient, where the skill gaps and staffing risk are, and what
the clinical notes add beyond the structured record.

This directory is intentionally **data only**. The dataset's answer key, planted-
effect magnitudes, generator, and scoring rubric live under `tests/eval/triage/`
and are **never** exposed to the agent under test (see that directory's README).

## Joins

```
assignments.patient_id             -> patients.patient_id
assignments.nurse_id               -> nurses.nurse_id
nurse_skills.nurse_id              -> nurses.nurse_id
nurse_skills.skill_id             -> skills_reference.skill_id
patient_required_skills.patient_id -> patients.patient_id
patient_required_skills.skill_id  -> skills_reference.skill_id
clinical_notes.patient_id          -> patients.patient_id
unit_snapshots.unit                -> nurses.home_unit
```

**Fan-out warning.** `assignments` joined to `patients` and `nurses` is
many-to-one and safe. Joining either *skills bridge* into that same view
multiplies rows and inflates every aggregate. Keep the bridges as separate
datasources (which is how the `.twbx` is built), and compute skill gaps with a
dedicated grouped query — the `triage_skill_gap` tool does this correctly.

Skill gap for an assignment:

```sql
SELECT a.assignment_id,
       COUNT(DISTINCT prs.skill_id) AS required,
       COUNT(DISTINCT ns.skill_id)  AS covered
FROM assignments a
JOIN patient_required_skills prs ON prs.patient_id = a.patient_id
LEFT JOIN nurse_skills ns
       ON ns.nurse_id = a.nurse_id AND ns.skill_id = prs.skill_id
GROUP BY a.assignment_id;
```

`assignments.skill_match_pct` is this ratio precomputed.

## Note on one column

`patients.mean_skill_match_pct` is a **validation aid**, not a legitimate analysis
input — it is a derived average of a patient's own assignment skill-matches.
Recovering the skill-match effect from `assignments.csv` is the real analysis;
reading it off `patients.mean_skill_match_pct` is circular. The agent-facing
Tableau datasource should exclude this column (a filtered publish step); until
then, the triage specialist is instructed not to cite it.

## Clinical notes

Free-text H&P / progress / discharge records for ~40 patients, internally
consistent with the structured record (age, sex, diagnosis, comorbidity, and home
meds all match). The comorbidity histories carry detail that exists in **no**
structured column — prior complications, discontinued drugs and why, imaging
dates, follow-up intervals. That is the extraction target: an agent that infers
from a note that anticoagulation was recently held for a GI bleed, and factors
that into bleeding risk, is doing something the structured data cannot support.
